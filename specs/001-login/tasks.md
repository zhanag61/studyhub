## T001 · 稳定密钥与会话配置（约 20–30 分钟）

- 前置：核对已确认 spec、当前分支与 Git 差异；不覆盖已有改动。
- Agent：修改 `config/settings.py`，必要时新增 `config/local_secret.py`；优先使用环境密钥，仅 DEBUG 模式首次创建并复用被忽略的 `.local-secret-key`；无效文件明确失败，不能覆盖已有密钥。配置数据库会话、7 天默认时长、正常关闭浏览器仍保留、非逐请求保存、命名登录/退出目的地。
- 可验证结果：两次加载本地配置得到同一密钥；环境密钥优先；生产缺密钥仍拒绝启动；私密文件未被 Git 跟踪。绝对登录截止时间在 T004 接入，不把默认 7 天配置当作已经实现 A012。
- 验收：临时目录测试首次创建、读取复用、文件无效与环境优先；检查生产配置失败行为和 `git check-ignore`；运行 Django check、迁移一致性。测试不打印实际密钥，不读写真实线上数据库。
- 你参与：看 Agent 用「重启前后是否相同」说明证据，可以用自己的话解释为什么密钥不能每次变化；不需要输入命令。
- 完成记录：配置测试证据、小提交及日志；此时尚无可用登录页面。

## T002 · 登录表单与模板（约 20–30 分钟）

- 前置：T001；复用现有 `base.html` 与样式结构。
- Agent：新增 `core/forms.py`、`core/templates/core/login.html`，补充表单样式；使用 Django 认证表单、中文标签与必填提示、统一错误信息、密码不回填、CSRF、可访问标签。暂不接入业务路由。
- 可验证结果：空字段和错误凭据呈现预期提示；用户名保留、密码 HTML 中无提交值；表单没有注册、找回或记住我选项。
- 验收：一次性数据库中的表单测试与模板渲染，覆盖空输入、错误密码、不存在/停用账号；模板中检查标签和 CSRF 结构。实际浏览器登录流程在 T004 验证。
- 你参与：对照 A004/A005 查看提示例子，说明错误反馈是否清楚；你可要求调整文案，改变已确认行为时先修规范。
- 完成记录：相关表单/模板测试、小提交；A002/A004/A005 仍等 HTTP 集成验收，不提前全部打勾。

## T003 · 准备本地测试账号（约 10–15 分钟）

- 前置：T001；Agent 明确核对数据库是本地 SQLite、内置迁移已应用。
- Agent：必要时应用本地内置迁移，使用 Django 用户创建方法准备普通启用账号 `learner_a`、`learner_b`。同名账号已存在时核对归属，不擅自重置；不写入 Neon、不创建真实测试者、不授予管理权限。
- 可验证结果：两个账号可作为独立身份使用；密码以哈希保存，实际凭据不进入公开文件或终端日志。
- 验收：只报告账号名、启用/权限状态；确认本机私有资料位于被忽略的 `.tools/qa/`。自动测试另用一次性数据库的虚构密码。
- 你参与：在本机私有资料中查看后续验收所需账号；不把密码复制到公开 Issue、PR 或提交。
- 完成记录：仅记录账号准备结果，不提交账号资料与数据库；可在下一次相关代码提交的日志中记录，本项不制造空提交。

## T004 · 接通登录与受保护工作台（约 30–45 分钟）

- 前置：T002、T003；会话与密钥配置就绪。
- Agent：在 `core/views.py`、`core/urls.py` 接入登录与受保护工作台，新增 `workspace.html`，更新公共导航。扩展 `LoginView`，成功与已登录访问均固定跳到工作台，忽略所有 `next`；成功登录后仅一次设置「当前时间 + 7 天」的绝对截止时间。工作台身份只取 `request.user`，响应禁止缓存。
- 可验证结果：未登录访问工作台先去登录；正确凭据显示当前用户名；错误/空输入留在表单；已登录不重复填表；两个独立客户端显示各自身份。
- 验收：HTTP 测试与本地浏览器覆盖 A001、A002、A004–A006、A008、A010、A011；查验成功登录的到期时间。A003 先验证工作台身份，退出按钮在 T006 与实际路由一同接入，不能放一个无效按钮假装完成。
- 你参与：用 Agent 提供的本地网址测试正确、错误密码和未登录直接访问，把实际现象与规范对照。
- 完成记录：相关测试、小提交、用户实际反馈；固定期限的边界证明留给 T005，完整功能尚未完成。

## T005 · 固定期限、独立会话与重启证据（约 20–35 分钟）

- 前置：T004；有真实会话和最小工作台可以请求。
- Agent：补充会话行为测试，使用可控时间；在自己管理的本地临时端口进程验证重启，不停止用户 8000 端口服务。
- 可验证结果：t0 登录得到 t0+7 天截止时间；t0+6 天浏览和合法会话写入不推迟它；到 t0+7 天即不能进入工作台；重新登录开始新 7 天。保留 Cookie、数据库与密钥重启后仍是同一未过期身份，截止时间不变；独立客户端仍独立。
- 验收：时间边界、到期 Cookie 重放、重新登录测试；真实本地进程重启前后请求。浏览器刷新/新标签页/正常关闭重开另记录实际操作，对应 A007、A008、A012；不等待一周。
- 你参与：按短步骤确认浏览器保留身份；理解「固定到期」与「每次刷新重新计时」的区别。
- 完成记录：区分可控时间、真实进程、浏览器三类证据；如重启或时间验证失败先修复再继续。

## T006 · POST 退出与旧会话失效（约 20–30 分钟）

- 前置：T004；可与 T005 分开推进，T007 前二者都须完成。
- Agent：扩展 `LogoutView` 并接入路由；工作台/公共导航添加带 CSRF 的 POST 退出按钮；成功固定回首页，忽略 `next`。使用 Django 退出清除当前服务器会话。
- 可验证结果：点击退出回首页，之后直接访问工作台先去登录；旧 Cookie 在另一个请求中也无法取得个人页；其他独立会话继续有效。GET 不能退出，缺失有效 CSRF 的 POST 被拒绝。
- 验收：启用 CSRF 检查的客户端验证成功 POST、403/405、固定首页跳转、旧 Cookie 重放；浏览器同会话两个标签页退出后重新请求。完成 A003 的退出按钮及 A009，不要求已打开页面实时消失。
- 你参与：点击退出，再访问工作台；反馈是否符合规范。
- 完成记录：退出与身份隔离测试、小提交、实际反馈。
