# 页面与请求契约

设计日期：2026-10-14；拟实现路径，当前没有新增路由。依据 [规范](../spec.md)。

## 创建页：/plans/new/，命名 core:plan-create

| 请求 | 身份/输入 | 预期响应 |
|---|---|---|
| GET | 已登录 | 200，三个字段、创建按钮、取消链接；不写入 |
| POST | 已登录、有效字段和 CSRF | 保存一份当前账号新计划；302 到 core:workspace |
| POST | 已登录、无效字段 | 200，同一绑定表单与精确错误；无新记录 |
| POST | 已登录、明确保存失败 | 200，同一表单与非字段错误；无成功消息、不凭内存实例显示卡片 |
| GET/合法 POST | 未登录、过期或退出 | 按已有规则 302 到登录；不保存；登录成功仍回工作台 |
| POST | 无有效 CSRF | 按 Django 既有保护 403，不写入 |
| PUT/PATCH/DELETE 等 | 已登录 | 405，不写入 |

创建只接收 title、description、target_date；日期控件传 ISO 年月日，空输入合法。
owner、owner_id、id、用户名等额外输入不参与归属或旧实例查找；有效创建始终归 request.user。
字段为空/长度越界/日期无效或过去时，错误文案严格按 spec，标题/说明及能识别日期保留。
取消为普通返回工作台链接，不提交数据。合法提交指通过既有 CSRF 检查，不改变安全中间件优先顺序。

创建页加 never_cache、login_required(login_url="core:login") 和 GET/POST 限制；
模板带 csrf_token，POST 才可写入。保留固定七天登录规则和已有 LoginView 目的地。

## 工作台：沿用 /workspace/，core:workspace

GET 只读取当前用户的 LearningPlan，默认 -created_at/-pk 排序。
没有记录时显示已确认空状态；有记录时显示每张本人卡片的完整标题、非空说明与目标日期。
日期用明确年月日，空日期为「未设置目标日期」。用户名、退出入口和原公开导航保留。
仅从存储读取卡片，不把失败创建的表单实例当结果；读取失败不伪造空记录或成功卡片。

成功写入正常提交后添加 messages.success("计划已创建")，然后 POST→302→GET。
工作台消费一次性成功消息；刷新仍显示记录，既不重复提交也不保证反复显示消息。
沿用 GET 限制、禁止缓存与未登录跳转，不新增每项计划的详情/编辑/删除端点或 JSON API。

## 展示与异常边界

默认模板自动转义，不使用 safe 或用户内容生成 HTML；说明用 pre-wrap 保留内部换行，
长标题/无空格文字用 overflow-wrap 避免手机溢出。表单有 label、错误关联、清楚必填/选填说明。
取消、创建、退出等核心控件保留触屏可用尺寸，320/390/1440px 由后续浏览器检查核对。

原始 HTML maxlength 不得限制规范允许的 strip 后长度；服务端为最终判断。
日期过去校验在 POST 时取北京时间，页面打开后跨午夜仍按提交日判断。

明确写入错误在 atomic 外捕获 DatabaseError，原表单添加「暂时无法保存，请稍后再试。」；
成功消息必须在 atomic 正常退出后添加，不自动重试。连接中断提交结果未知时不承诺无记录。
错误诊断不得回显连接串、异常对象或私有凭据，日志不得记录用户提交内容。
正常绑定表单与本人卡片按规范保留或展示输入，并自动转义。
