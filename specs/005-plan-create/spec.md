## User Scenarios & Testing *(mandatory)*

### User Story 1 - 保存一个学习目标并在工作台看到它 (Priority: P1)

已有账号的学习者从「我的工作台」进入「创建学习计划」，填写标题，
按需填写说明和目标完成日期。保存成功后回到自己的工作台，看到新卡片，
下次回来还可以找到这份计划。

**Why this priority**: 给后续任务与进度提供一个真实保存的学习目标，是本轮最小可用结果。

**Independent Test**: 已登录账号完成一次创建，检查成功提示与卡片，
再刷新、退出后重新登录，核对内容仍在且没有多出计划。无需任务、编辑或详情页。

**Acceptance Scenarios**:

1. **Given** learner_a 已登录且没有计划，**When** 打开工作台，
   **Then** 能找到「创建学习计划」入口及「还没有学习计划，先创建一个小目标吧。」的空状态。
2. **Given** 提交时北京时间为 2026-10-14，**When** learner_a 提交标题「Python 入门」、
   说明「每天练习 20 分钟」和日期 2026-10-21，
   **Then** 恰好保存一份属于 A 的计划，回到「我的工作台」，
   显示「计划已创建」和包含上述三项内容的新卡片。
3. **Given** learner_a 已登录，**When** 只填写「读完一本书」并提交，
   **Then** 创建成功，说明为空、日期未设置；卡片显示标题及「未设置目标日期」，
   不自动填入说明或当天日期。
4. **Given** 已创建一份计划，**When** 刷新工作台或退出后重新登录，
   **Then** 原卡片及内容仍在，计划数量不因这些操作增加。
5. **Given** 已有「Python 入门」，**When** 再次主动提交同名计划，
   **Then** 新增另一份独立计划，两张卡片分别保留各自说明与日期，不覆盖旧计划。
6. **Given** 已有自己的计划，**When** 再创建一份新计划并返回工作台，
   **Then** 新卡片位于已有卡片之前，原计划继续可见。
7. **Given** 用户已填写表单但未提交，**When** 选择「取消」返回工作台，
   **Then** 不新增计划。

### User Story 2 - 看懂错误并保留输入以便修改 (Priority: P2)

填写不符合要求时，学习者留在创建页，看到对应字段的清楚提示，
可以修正原内容后再提交，不会误以为计划已经保存。

**Why this priority**: 避免空目标、误填日期和反复重输，保证保存的是用户真正想记录的内容。

**Independent Test**: 在创建页提交空标题、越界长度和无效日期；
核对字段提示、输入保留及自己的计划数量不变，再修正后成功创建。

**Acceptance Scenarios**:

1. **Given** 用户已填写说明和有效日期，**When** 标题为空或仅含空白并提交，
   **Then** 留在创建页，提示「请输入计划标题」，保留说明与有效日期，不新增计划。
2. **Given** 去掉首尾空白后的标题有 100 个字符，**When** 其他字段有效并提交，
   **Then** 可创建；101 个字符时提示「标题不能超过 100 个字符」且不创建。
3. **Given** 去掉首尾空白后的说明有 1000 个字符，**When** 其他字段有效并提交，
   **Then** 可创建；1001 个字符时提示「说明不能超过 1000 个字符」且不创建。
4. **Given** 提交时北京时间为 2026-10-14，**When** 日期为空、2026-10-14 或 2026-10-21，
   **Then** 该日期字段有效；2026-10-13 时提示「目标完成日期不能早于今天」且不创建。
5. **Given** 日期填写为不存在或无法识别的日期，**When** 提交，
   **Then** 提示「请输入有效的目标完成日期」，保留标题、说明，不创建。
6. **Given** 校验失败，**When** 用户修正后重新提交，
   **Then** 正常创建一份计划；之前失败的尝试没有产生额外记录。
7. **Given** 标题和说明首尾有空白，**When** 内容有效并保存，
   **Then** 首尾空白去除，说明内部的空格与换行保留；仅空白的说明按未填写处理。

### User Story 3 - 每个账号只看到自己的计划 (Priority: P1)

已有账号仅为自己创建计划；工作台不暴露其他人的标题、说明或日期。
这项边界与正常创建一起交付，不能留到以后补。

**Why this priority**: 学习计划属于个人内容，是已确认的多用户产品边界。

**Independent Test**: A、B 各自创建计划，用两个独立登录会话核对各自工作台；
未登录和尝试指定其他账号的提交不能获得别人的内容或替别人创建。

**Acceptance Scenarios**:

1. **Given** A 创建「Python 入门」，B 尚未创建，**When** B 打开自己的工作台，
   **Then** 看不到 A 的卡片，显示 B 自己的空状态；A 的卡片仍在。
2. **Given** A、B 各创建一份同名计划，**When** 分别打开工作台，
   **Then** 各自仅看到自己那一份及本人填写的说明和日期。
3. **Given** 未登录或登录已过期，**When** 打开创建页或提交创建，
   **Then** 进入现有登录流程，不保存计划，不返回个人内容；
   登录成功沿用回工作台的规则，再由用户进入创建页。
4. **Given** A 已登录，**When** 提交信息试图指定 B 为计划所属账号，
   **Then** 不能在 B 名下产生计划；成功保存的计划始终属于实际登录的 A。
5. **Given** A 退出后同一浏览器登录 B，**When** 重新请求工作台，
   **Then** 不再取得 A 的卡片，只显示 B 的内容。

### Edge Cases

- 没有计划时保留创建入口和空状态；有计划后用本人卡片区替代空状态。
- 日期只表示年月日，不含时分秒；按**提交时的北京时间日期**判断，跨午夜按新的当天判断。
- 空日期不等于今天；目标日期经过后，已有计划继续保存和展示，本轮不自动删除或改状态。
- 日期能识别但属于过去时，原日期留给用户修改；非法日期控件若无法显示原值，
  错误提示仍须清楚指出日期无效，标题与说明保留。
- 用户输入含看似页面标记的文字时，作为普通文字展示，不执行或改变页面行为。
- 创建成功后刷新工作台不重复保存；再次主动提交有效内容是另一次创建，
  本轮不承诺网络重试或连续快速提交的自动去重。
- 明确保存失败时不给成功提示，不伪造卡片；保留可恢复的输入并提示
  「暂时无法保存，请稍后再试。」。连接中断导致结果无法确认时，不承诺自动重试。
- 在创建页登录过期时，不替任何账号保存；重新登录后不承诺自动恢复未提交表单。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 已登录用户必须能从「我的工作台」进入「创建学习计划」，看到标题、
  说明、目标完成日期，以及「创建计划」「取消」操作。
- **FR-002**: 标题必须填写，去掉首尾空白后为 1–100 个字符；
  说明选填，去掉首尾空白后最多 1000 个字符，允许内部换行。
- **FR-003**: 目标完成日期选填；填写时必须是真实可识别的日期，
  且不早于提交时北京时间的当天。未填写时保持未设置。
- **FR-004**: 保存时标题和说明去掉首尾空白，仅空白的说明视为空；
  中间空格以及说明换行保留，不主动改写用户的学习目标。
- **FR-005**: 空标题、长度越界、无效日期与过去日期必须使用上述具体字段提示；
  校验失败留在创建页，保留标题、说明和能识别的日期，不保存计划。
- **FR-006**: 每次正常的有效创建提交成功时，必须保存一份独立计划，
  归属实际登录用户，保存标题、说明、目标日期和创建顺序信息。
- **FR-007**: 同一用户以及不同用户都可使用相同标题；新计划不能覆盖或合并旧计划。
- **FR-008**: 保存成功后必须回「我的工作台」，显示「计划已创建」；
  新卡片在前，仅展示本人计划，显示完整标题、非空说明与目标日期。
  日期未设置时显示「未设置目标日期」，空说明不生成虚构内容。
- **FR-009**: 没有本人计划时显示上述空状态与创建入口；有计划时显示本人卡片区，
  保留当前身份和退出能力。卡片只提供本轮创建验收所需展示，不增加详情或编辑入口。
- **FR-010**: 刷新、退出后重新登录及正常重启应用后，已保存计划仍属于原用户、
  内容不丢失，也不因读取工作台新增记录。成功提示不要求每次刷新重复出现。
- **FR-011**: 只有有效登录用户可创建或读取本人卡片；用户不能通过更改提交信息
  为另一个账号创建计划，也不能取得另一个账号的计划内容。
- **FR-012**: 未登录、登录过期和退出后的访问沿用既有登录规则；
  登录成功仍回工作台，不改变现有登录目的地或七天期限。
- **FR-013**: 取消或未提交表单不创建计划；明确保存失败不显示成功或伪造卡片。
- **FR-014**: 输入和卡片按普通文字处理；电脑与手机上字段、错误提示、操作均可使用，
  核心流程不依赖横向滚动。

### Key Entities *(include if feature involves data)*

- **学习计划**：一份独立的个人学习目标，包含标题、选填说明、选填目标完成日期，
  并关联所属账号与创建顺序；同名计划仍是不同的计划。
- **已有账号**：沿用当前登录身份，一个账号可拥有多份计划；
  只有该账号可在自己的工作台取得这些计划。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 标题有效时，说明/日期四种选填组合均可各保存恰好一份计划；
  成功回工作台，提示和卡片内容与保存输入一致。
- **SC-002**: 空白标题、101 字符标题、1001 字符说明、过去日期和非法日期
  均不能新增计划，并给出对应提示；边界 100/1000 字符以及当天日期可用。
- **SC-003**: 保存后刷新、退出并重登及正常重启再访问，卡片内容仍一致，
  计划数量不因这些读取操作增加。
- **SC-004**: A、B 独立创建与同名创建时，所有工作台展示均只属于当前账号；
  未登录访问和指定他人账号的提交不能取得或写入他人的计划。
- **SC-005**: 电脑及宽度不小于 320px 的手机页面可完成填写、修正错误、创建和查看新卡片，
  无需横向滚动即可操作关键控件。

### 随整份规范已确认的默认值

- 标题最多 100 字符、说明最多 1000 字符；汉字、字母、数字各按一个字符计，
  不按存储字节计算。输入按普通文字处理，说明可换行。
- 首尾空白去除；取消不保存；卡片按新建在前排列；日期未设置采用明确文字。
- 按当前项目使用的北京时间判断日期。具体提示、失败恢复和手机展示按本稿验收。
- 已保存的历史计划即使目标日期已过去仍能展示；创建日的日期限制不追溯删除已有数据。
- 本轮用已有本地测试账号验证，生产账号、真实邀请与上线另按课程推进。

### 范围与依赖

- 依赖已交付的用户名密码登录、个人工作台、当前身份和退出行为。
- 本轮包含创建入口、输入验证、保存、本人工作台卡片以及必要的身份/账号边界。
- 独立计划列表/详情页、编辑、删除、搜索、任务、进度、提醒、自动生成计划、
  注册和密码找回均在后续功能确认，不是本轮交付条件。
- 本规范课只生成 spec、需求质量清单与课程记录，暂不生成 plan/tasks、业务模型、
  页面实现、迁移、账号或生产发布。
