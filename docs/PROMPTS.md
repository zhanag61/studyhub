# 发给 Agent 的指令

这里的文字发到 **Codex 聊天**，不输入 PowerShell。方括号是要替换的内容。终端命令由 Agent 根据当前仓库给出。

## 1. 开课 / 恢复

> 进入 StudyHub 老师兼 Agent 模式。读取项目说明、课程日志、当前规范和 Git 状态。告诉我已经完成什么，本课只完成哪个可见行为，以及怎样验收。先解释必要概念，再区分我亲手操作的步骤和你执行的步骤。

## 2. 需求规范

> 本课只做「[创建学习计划]」。先问清会影响行为的需求，再写 spec.md，包含使用场景、范围、验收条件和不包含的内容。用具体例子让我确认，暂时不实现代码。

## 3. 技术计划

> 根据已确认的规范和现有代码编写 plan.md。解释数据怎样从页面进入数据库，再显示出来；说明模型、页面和关键错误处理的必要改变。采用适合当前项目的最小方案。

## 4. 拆任务

> 把方案拆成 tasks.md。每项任务写清前置条件、可验证结果和验收方法，大小适合一课完成。标明你实现什么、我亲手练习什么，并指出第一项任务。

## 5. 功能分支

> 检查工作区和当前分支，为这项功能给出准确的建分支命令，逐条解释。若存在未提交修改，先确定它们属于哪项任务，再安排操作。

## 6. 实现一个任务

> 只实现任务 [T001]，依据已确认规范完成必要修改。解释关键代码，运行相关检查，再给我浏览器验收步骤。完成后安排一个我能亲手做的小修改。

## 7. 验收与提交

> 对照规范检查结果，列出操作步骤和预期结果。检查正常流程、关键错误及数据权限。根据实际差异给出准确的 git add 命令和提交信息，并解释本次提交保存了什么。

## 8. PR 与审查

> 为本功能准备 PR，描述实际行为和验证结果，关联对应 Issue。让另一个 Agent 按规范只读审查差异，报告具体问题、影响和复现方法；我负责实际使用验收。

## 9. 合并与发布

> 汇总审查结果、修复情况和验收证据。给我在 GitHub 合并的步骤，以及合并后同步本地 main 的命令。若本次需要发布，再给出发布、上线检查和回退步骤。

## 10. 结束本课

> 更新课程日志：本课成果、确认的决定、验收结果、提交或 PR、我学会的概念、未解决的问题，以及下一课第一步。确保新聊天也能依据仓库继续教学。

## 遇到错误

> 我执行了 [命令或操作]，预期 [结果]，实际 [现象]，完整报错如下：[报错]。先解释原因，再给最小修复方案；修复后验证原操作，并记录原因。

只贴相关报错，不贴密码、数据库连接串或服务密钥。

## 接入 Spec Kit 后

> 本课继续使用已安装、记录版本的 Spec Kit。先核对当前 Git 分支和活动规范目录，再执行本课需要的规范、计划或任务步骤。不要仅因为切换分支就认为规范上下文已切换。

## 第一课完整指令

> 开始 StudyHub 的 M0-L01，按已确认路线结对教学。项目目录是 D:\developer\studyhub，使用 Python 和 Django 5.2 LTS。先读取已有项目与课程日志，再指导我亲手启动首页。每组 PowerShell 命令先解释用途，等待我反馈结果再继续。本课目标是我能看到首页，在功能分支修改一句文字，并解释启动过程。结束时记录真实进度。
