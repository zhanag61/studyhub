# 课程路线：M0–M8

每周 5–8 小时，初始排期 16–20 周。每课约 60–90 分钟，额外时间用于亲手练习与验收；时间不代替完成标准。

2026-10-08 起按用户最新要求调整：默认由 Agent 执行终端、Git、实现与检查，用户练习写清需求、确认规范和验收结果。下表的 Git、部署命令均由 Agent 优先执行；亲手命令练习为选学。

## 如何开一课

把下面这条发到聊天中，将课程编号和目标换成表中的对应行：

> 开始 StudyHub 的 [M2-L02]，本课目标是 [创建自己的学习计划]。先读取课程日志、当前规范和 Git 状态。由你执行实现、Git 和检查，解释必要概念；我负责确认需求和浏览器验收。用一个可见结果验收，结束时更新课程日志。

要恢复进度可以直接发：

> 继续 StudyHub 下一课。先根据仓库中的课程日志确认下一步，不要假设我已经完成上次的手工验收。

## 课程表

| 课程 | 本课目标 | 学习与参与 | 完成标准 |
|---|---|---|---|
| M0-L01 | 启动欢迎首页 | 运行项目、辨认请求流程、在分支修改文案 | 浏览器显示新文案，能解释改动 |
| M0-L02 | 让 Agent 保存功能版本 | 发出范围明确的提交指令，理解保存结果 | 提交只含本课明确改动 |
| M0-L03 | 连接 GitHub，完成首次 PR | 指挥 Agent 建仓、推送和准备 PR，查看差异 | 能解释本地、远端、分支与 PR |
| M0-L04 | 部署空页面，验证实际访问 | 连接托管、核对费用、国内网络打开页面 | 真实网址可访问；失败时保留明确待办 |
| M1-L01 | 手工写登录规范 | 用例、范围、验收例子 | 预期行为已确认，尚未写业务代码 |
| M1-L02 | 写登录计划并拆任务 | 读请求流程、识别 Django 认证能力 | 每个任务有前置条件和验收方法 |
| M1-L03 | 完成测试账号登录 | 正确、错误密码及未登录场景 | 预期页面与错误提示一致 |
| M1-L04 | 退出、验证、审查与合并 | 操作账号、读测试结果、读 PR 差异 | 第一项手工 SDD 功能形成完整闭环 |
| M2-L01 | 引入 Spec Kit | 核对版本与活动规范、映射已学流程 | 固定版本，第一轮工具规范经过确认 |

| M2-L04 | 删除与所有权验证 | 两账号、直接网址、删除确认 | 无法读写别人的计划 |
| M3-L01 | 给计划添加任务 | 关联数据与表单 | 新任务归属正确计划 |
| M3-L02 | 修改和删除任务 | 修改字段、处理无效对象 | 正确保存，权限检查有效 |
| M3-L03 | 完成与取消完成 | 状态更新、重复操作 | 操作不会重复累计完成数 |
| M3-L04 | 显示学习进度 | 空计划、部分完成、全部完成 | 进度按数量计算且可回退 |

## 每课固定交付

一个可展示结果；本课确认的规范或任务；真实检查结果；用户实际参与的决定与验收；一个聊天指令练习；更新后的课程日志。

注册、计划、任务、笔记等具体规格在相应课程确认，避免把整个项目一次性生成后再补解释。后续阶段的任务在课程日志保持未开始。
