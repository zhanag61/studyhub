# M0-L04：让别人也能打开 StudyHub 首页

## 本课目标

把已验收的首页部署到 Render Free，用 Neon Free PostgreSQL 保存线上数据库。你通过聊天指定目标，Agent 执行代码、检查和 Git；你在电脑和手机上确认真实访问。实际状态以[部署记录](../DEPLOYMENT.md)与[课程日志](../LEARNING_LOG.md)为准。

## 只学一个概念：本地和线上

`127.0.0.1` 指当前设备。手机输入这个地址会访问手机自己，无法看到你电脑上的 StudyHub。上线后，Render 的服务器持续运行 Python，浏览器通过公开 HTTPS 地址访问它。

请求流程仍然是「网址 → Django 视图 → 模板 → 页面」。线上多了一层 Render 的 HTTPS 代理，Gunicorn 负责运行 Django，WhiteNoise 负责发送 CSS 和图标。源码保存在 GitHub，数据库保存在 Neon，密钥放在服务配置中；这些各有自己的作用。

## 发到聊天里的指令

> 开始 StudyHub M0-L04。只部署现有首页，使用已确认的 Render Free 和 Neon Free，不购买付费服务。由你完成配置、检查、PR 和上线；需要我登录或确认资源位置时，说明具体入口。我负责普通网络和手机验收。分别记录代码准备、实际上线、用户反馈。

账号连接后还要选定 Render 工作区和 Neon 项目。只发项目页面网址或项目 ID；密码与数据库连接串由 Agent 从连接工具取得并注入服务，不发在聊天里。

## Agent 的实施与检查

规范保存在 `specs/004-deployment/`，对应 Issue #3。短期分支为 `feat/m0-render-deploy`。Agent 先实现并检查，再创建 PR，经过 Linux CI 和独立 Agent 审查后合并 main，最后用 main 创建免费服务。

本地检查包括原首页、正式模式请求、静态文件、错误域名、HTTPS 跳转及缺少配置时拒绝启动。Windows 使用相同 WSGI 应用验证请求；Linux CI 使用真实 Gunicorn 和一次性的 PostgreSQL 数据库验证迁移。两类证据分开记录。

以下 **PowerShell 命令供选学**，默认 Agent 执行：

```powershell
Set-Location 'D:\developer\studyhub'
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe scripts/check_deployment.py
```

最后一条启动自己的一次性测试服务器，不占用你正在使用的 8000 端口；本地默认不连接真实 Neon 数据库。

## 你在浏览器验收

等 Agent 提供真实上线网址后：

1. 在电脑普通网络打开，确认主标题「今天，给自己的成长留一点时间。」和工作台标题「在这里，收好你的每一点进步。」。
2. 刷新，确认配色、图标和「认识你的工作台」滚动按钮正常。
3. 在手机浏览器打开同一网址，确认文字没有横向溢出，页面能正常滚动。
4. 发给 Agent：「电脑打开结果……；手机打开结果……；首次等待约……秒；样式或报错……」。

Render Free 闲置后会休眠，第一次访问可能需要等约一分钟。Agent 的网络请求成功不能替代你在实际网络上的结果。
