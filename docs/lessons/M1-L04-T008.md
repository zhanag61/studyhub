## 一个概念：完成代码后，还要确认什么

PR 是把功能分支的成果交回 `main` 的入口。打开 [StudyHub 仓库](https://github.com/zhanag61/studyhub) → **Pull requests** → **Closed** → **PR #7**，可以看最终行为、验证证据和合并结果；**Files changed** 显示具体改动，**Checks** 显示 GitHub 真正运行的自动检查。

CI 回答“别人从干净环境取这份代码，是否也能运行并通过检查”；另一位 Agent 对照规范阅读实现，寻找测试可能遗漏的问题；你的浏览器反馈回答“实际用起来是否符合预期”。这些证据各有用途，课程日志分别记录，不把其中一种替代另一种。

Squash and merge 将功能分支上的多个小提交整理成 `main` 的一个提交。本轮是 `f2248aa`；原分支上的提交仍可在 PR 中追溯。合并表示主分支接收了功能，部署表示线上服务真的运行了该版本，二者需要分别核对。
