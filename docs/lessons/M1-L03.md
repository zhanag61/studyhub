## 一个概念：重启要复用同一枚印章

`SECRET_KEY` 可以理解为 Django 核验会话的印章。以后登录记录由 Django 签名，读取时再检查签名；重启后换了印章，就可能认不出原来的有效记录。它是服务器的配置密钥，不是用户密码，也不是把会话内容加密的工具。

本次把本地印章保存在 `.local-secret-key`：首次生成，以后读取复用。若设置了环境变量 `DJANGO_SECRET_KEY`，优先使用环境变量；文件为空、损坏或不可读时明确失败，保留已有文件。密钥和创建时的临时文件都被 Git 忽略，不打开或打印实际值来验收。

首次创建先写完同目录的临时文件，再发布到最终文件名；另一个进程先创建成功时，读取它的完整密钥，不覆盖。Windows 使用不覆盖目标的重命名，POSIX 使用硬链接。

## 本次配置了什么

以下默认值仅在本地 DEBUG 模式生效，生产配置保持原样：

| 配置 | 默认值及含义 |
|---|---|
| SESSION_ENGINE | 数据库会话，服务器保存记录 |
| SESSION_COOKIE_AGE | 604800 秒，即 7 天 |
| SESSION_EXPIRE_AT_BROWSER_CLOSE | False，正常关闭浏览器不主动结束 Cookie |
| SESSION_SAVE_EVERY_REQUEST | False，不因每次请求都保存会话 |
| SESSION_COOKIE_HTTPONLY | True，页面脚本不能读取会话 Cookie |
| LOGIN_URL / LOGIN_REDIRECT_URL / LOGOUT_REDIRECT_URL | core:login / core:workspace / core:home，约定后续的命名目的地 |

默认 7 天是准备工作。成功登录时设置绝对截止时间属于 T004，期限边界和会话重启验证属于 T005；本次没有证明 A007 或 A012 已通过。命名目的地也没有自动生成页面，目前仍只有原有首页等路由。

配置含义可查 [Django 5.2 会话文档](https://docs.djangoproject.com/en/5.2/topics/http/sessions/)与[密钥说明](https://docs.djangoproject.com/en/5.2/ref/settings/#secret-key)。
