## 一个概念：页面展示与数据保存

之前的首页文字由 Python 提供，浏览器拿到 HTML 就能显示。计划还需要数据库：关闭页面、退出账号后，目标仍要留着。

以 A 创建「Python 入门」为例：

1. 浏览器显示创建表单。A 输入标题、选填说明与日期，点击「创建计划」。
2. 浏览器发送这三个字段；登录 Cookie 自动随请求送到服务器，Django 由此恢复 A 的有效身份。
3. 创建表单去掉首尾空白，检查长度与提交时北京时间日期。失败时返回原输入和中文提示，尚未写入数据库。
4. 有效时，服务器把所属账号指定为 A，在数据库新增一份计划。保存明确成功后才发成功提示并让浏览器转到工作台。
5. 工作台从数据库只读取 A 的计划，再渲染成卡片。B 登录时只查询 B 的记录；刷新只是读取，不会再创建。

Cookie 记录登录关系，数据库保存学习内容。表单里的 owner 即使被人改成 B，服务器也不采用它。技术数据流图和字段决策见 [plan.md](../../specs/005-plan-create/plan.md)。

「模型」是数据库记录的结构；「表单」负责检查输入；「视图」连接请求、表单和存储；「模板」把结果写成 HTML。复用 Django 的这些能力，不另造一套前后端。

## 为什么第一步不直接写整个页面

T001 先明确一条计划记录有哪些字段，生成描述建表变化的「迁移文件」，在临时测试数据库验证。
此时原数据库和页面保持当前行为；T003 在接通创建页之前才对已核对的本地 SQLite 应用迁移。
这样一次只需要判断一类变化，出错也容易定位。

已保存计划的目标日期可能过去，因此日期的“今天或未来”只在创建时检查；不能给数据库加一个永久拒绝历史记录的规则。
创建需要新记录，同名不覆盖；成功后刷新只读已有数据。
