## 只学两个概念

**提交**是带说明的项目快照。编辑器保存文件后，还要由 Git 提交，才能在版本历史中找到这次改动。

**分支**是一条独立的修改路线。本次在功能分支保存首页改动，main 仍保留起步版本；之后通过 PR 比较并合并。

## 发到聊天里的练习

> 检查当前分支和差异，把我已经验收的首页改动保存为提交。个人文案与页面配色分开保存。由你执行 Git 和相关检查，告诉我保存了什么、提交编号，以及是否存在未提交修改。

Agent 收到这样的指令后，应检查实际文件与暂存内容，按范围提交并验证结果。用户无需逐条复制命令；用户的重点是明确要保存哪些内容，判断结果是否符合需求。

本课已经执行这项工作，不需要为了练习重复提交。

## 本次排错记录

仓库由 Agent 的 CodexSandboxOffline 账户创建，用户 PowerShell 使用 Zrx 账户，Git 因所有者不同报 `detected dubious ownership`。用户已在自己的 Git 配置中加入这个已知项目的信任记录，后续 git status 已正常读取仓库。

以下是当时使用的修复命令，仅作参考：

```powershell
git config --global --add safe.directory D:/developer/studyhub
```

它只把指定路径加入当前用户的信任列表。参考：[Git 官方 safe.directory 说明](https://git-scm.com/docs/git-config#Documentation/git-config.txt-safedirectory)。

用户随后反馈差异命令仍有问题，本轮没有具体错误文本。Agent 使用无分页输出检查成功，不能据此断言用户终端的具体错误原因。以后由 Agent 接手此类排错，不要求用户反复执行命令。

## 可选：查看结果的命令

想了解命令时可以阅读；默认由 Agent 执行。

```powershell
git status
git --no-pager log --oneline -3
git --no-pager show --stat HEAD
```

它们分别查看当前状态、最近的提交、最后一次提交包含的文件。
